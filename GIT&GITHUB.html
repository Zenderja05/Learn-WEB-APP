GIT

GIT คืออะไร

GIT เป็นระบบควบคุมเวอร์ชันแบบกระจาย (Distributed Version Control System) ที่ช่วยให้ผู้พัฒนาสามารถติดตามการเปลี่ยนแปลงของโค้ดและทำงานร่วมกันได้อย่างมีประสิทธิภาพ GIT ถูกพัฒนาโดย Linus Torvalds ในปี 2005 เพื่อช่วยในการพัฒนาเคอร์เนลของลินุกซ์

คุณสมบัติของ GIT

  • การควบคุมเวอร์ชันแบบกระจาย: ทุกคนที่ใช้ GIT จะมีสำเนาของรีโพซิทอรีทั้งหมด ทำให้สามารถทำงานแบบออฟไลน์ได้
  • การจัดการสาขา (Branching): GIT มีระบบสาขาที่มีประสิทธิภาพ ทำให้สามารถสร้างและรวมสาขาได้ง่าย
  • ประสิทธิภาพสูง: GIT ถูกออกแบบมาให้มีประสิทธิภาพสูงในการจัดการกับโปรเจกต์ขนาดใหญ่
  • ความปลอดภัย: GIT ใช้การเข้ารหัส SHA-1 เพื่อรักษาความสมบูรณ์ของข้อมูล

ทำไมต้องใช้ GIT

  • การทำงานร่วมกัน: GIT ช่วยให้ทีมพัฒนาสามารถทำงานร่วมกันได้อย่างมีประสิทธิภาพ
  • การติดตามการเปลี่ยนแปลง: GIT ช่วยให้สามารถติดตามการเปลี่ยนแปลงของโค้ดและย้อนกลับไปยังเวอร์ชันก่อนหน้าได้ง่าย
  • การจัดการโค้ดที่ดีขึ้น: GIT ช่วยให้สามารถจัดการโค้ดได้อย่างเป็นระบบและมีระเบียบ

คำสั่งพื้นฐานของ GIT

  • git init: สร้างรีโพซิทอรี GIT ใหม่
  • git clone [url]: คัดลอกรีโพซิทอรีจากระยะไกลมายังเครื่องของคุณ
  • git add [file]: เพิ่มไฟล์ไปยังสเตจเพื่อเตรียมพร้อมสำหรับการคอมมิต
  • git commit -m "[message]": บันทึกการเปลี่ยนแปลงที่ถูกสเตจไว้พร้อมข้อความบรรยาย
  • git push: ส่งการเปลี่ยนแปลงไปยังรีโพซิทอรีระยะไกล
  • git pull: ดึงการเปลี่ยนแปลงจากรีโพซิทอรีระยะไกลมายังเครื่องของคุณ
  • git --help: แสดงคำสั่งทั้งหมดของ GIT

Git CLI

Git CLI คืออะไร

Git CLI (Command Line Interface) เป็นเครื่องมือที่ใช้ในการโต้ตอบกับระบบควบคุมเวอร์ชัน GIT ผ่านทางบรรทัดคำสั่ง ผู้ใช้สามารถใช้คำสั่งต่าง ๆ เพื่อจัดการรีโพซิทอรี GIT เช่น การสร้างสาขา, การคอมมิต, การดึงข้อมูลจากรีโมท และอื่น ๆ อีกมากมาย Git CLI เป็นวิธีที่มีประสิทธิภาพและยืดหยุ่นสำหรับการทำงานกับ GIT

คำสั่งพื้นฐานของ Git CLI

  • git status: แสดงสถานะปัจจุบันของรีโพซิทอรี
  • git log: แสดงประวัติการคอมมิตในรีโพซิทอรี
  • git branch: แสดงรายการสาขาที่มีอยู่ในรีโพซิทอรี
  • git checkout [branch]: เปลี่ยนไปยังสาขาที่ระบุ
  • git merge [branch]: รวมสาขาที่ระบุเข้ากับสาขาปัจจุบัน

Git GUI

Git GUI คืออะไร

Git GUI เป็นเครื่องมือที่มีอินเทอร์เฟซกราฟิกสำหรับการจัดการรีโพซิทอรี GIT ช่วยให้ผู้ใช้ที่ไม่คุ้นเคยกับบรรทัดคำสั่งสามารถทำงานกับ GIT ได้ง่ายขึ้น โดยมีฟีเจอร์ต่าง ๆ เช่น การดูสถานะของไฟล์, การคอมมิต, การสร้างสาขา และการรวมสาขา ผ่านทางหน้าต่างกราฟิก

ตัวอย่างโปรแกรม Git GUI

  • GitKraken
  • Sourcetree
  • GitHub Desktop
  • TortoiseGit

Extention Git graph

Extention Git graph คืออะไร

Git Graph เป็นส่วนขยาย (Extension) สำหรับ Visual Studio Code ที่ช่วยให้ผู้ใช้สามารถดูและจัดการรีโพซิทอรี GIT ผ่านทางอินเทอร์เฟซกราฟิกที่ใช้งานง่าย Git Graph แสดงประวัติการคอมมิตในรูปแบบกราฟ ทำให้ผู้ใช้สามารถเข้าใจโครงสร้างของสาขาและการเปลี่ยนแปลงได้อย่างรวดเร็ว

คุณสมบัติของ Extention Git graph

  • แสดงประวัติการคอมมิตในรูปแบบกราฟ
  • รองรับการสร้าง, ลบ, และสลับสาขา
  • รองรับการคอมมิต, การรีเบส, และการรวมสาขา
  • สามารถดูรายละเอียดของคอมมิตแต่ละรายการได้

มีใช้งานยังไงบ้าง

    สร้างบรานช์ยังไง

  • คลิกขวาที่คอมมิตที่ต้องการสร้างสาขาใหม่
  • เลือก "Create Branch Here"

    • สลับบรานช์ยังไง

  • คลิกขวาที่สาขาที่ต้องการสลับไป
  • เลือก "Checkout Branch"

    • ลบบรานช์ยังไง

  • คลิกขวาที่สาขาที่ต้องการลบ
  • เลือก "Delete Branch"

    • คอมมิทจากบรานช์รองไปบรานช์หลักยังไง

  • คลิกขวาที่สาขารองที่ต้องการคอมมิต
  • เลือก "Merge Branch into Current Branch"

GITHUB

GITHUB คืออะไร

GitHub เป็นแพลตฟอร์มโฮสติ้งสำหรับรีโพซิทอรี GIT ที่ให้บริการบนคลาวด์ ช่วยให้ผู้พัฒนาสามารถเก็บโค้ดของตนในที่เดียวและทำงานร่วมกับผู้อื่นได้อย่างง่ายดาย GitHub ยังมีฟีเจอร์ต่าง ๆ เช่น การติดตามปัญหา (Issue Tracking), การจัดการโครงการ (Project Management), และการทำงานร่วมกันผ่าน Pull Requests

Github page

GitHub Pages เป็นบริการที่ให้ผู้ใช้สามารถโฮสต์เว็บไซต์สถิติโดยตรงจากรีโพซิทอรี GitHub ของตนได้ โดยไม่ต้องมีเซิร์ฟเวอร์แยกต่างหาก GitHub Pages เหมาะสำหรับการสร้างบล็อก, เว็บไซต์ส่วนตัว, หรือเอกสารโครงการ โดยสามารถใช้ Jekyll เพื่อสร้างเว็บไซต์แบบไดนามิกได้ง่ายขึ้น

มีขั้นตอนการสร้าง GitHub Pages

  1. สร้างรีโพซิทอรีใหม่บน GitHub หรือใช้รีโพซิทอรีที่มีอยู่แล้ว
  2. ไปที่การตั้งค่า (Settings) ของรีโพซิทอรีนั้น
  3. เลื่อนลงไปที่ส่วน GitHub Pages
  4. เลือกแหล่งที่มาของเนื้อหาเว็บไซต์ (เช่น สาขา main หรือโฟลเดอร์ docs)
  5. บันทึกการตั้งค่าและรอให้ GitHub สร้างเว็บไซต์
  6. เข้าถึงเว็บไซต์ของคุณผ่าน URL ที่ GitHub จัดเตรียมให้
